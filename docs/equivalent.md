# C-equivalent functions

Functions whose compiled C behaves like the original under differential execution
(`tools/equiv.py`): same `jal` targets, same memory writes, same `$v0`/`$v1`.
These are **not** byte-identical, so they stay in `nonmatching/`; the evidence is
behavioural, not a proof. Byte equality remains the stronger result.

Emulation: Unicorn MIPS64, R5900 `sq`/`lq` lowered to `sd`/`ld` (GPR spills).
Case: zero-initialised memory, zeroed `a0`-`a3`; branches on arguments therefore
exercise one path until richer cases exist.

Limits of this evidence:

- Each function runs once, with zeroed arguments. Branches that depend on arguments exercise
  only one path, and a result of `v0v1=(0, 0)` can come from either version failing the same way.
- Rows with `writes=0/0 calls=0/0` compare only return registers. 428 of the 1512 rows below are
  of that kind; treat them as weak.
- Indirect calls through uninitialised pointer tables end at PC 0 and cannot be judged, so such
  functions are not listed.
- Only functions that are still non-matching drafts appear here. A function that later became a
  byte-exact match is removed, because byte equality supersedes this evidence.

Needs the `unicorn` package (`requirements.txt`). Run it as
`PES6_TARGET=<image> python tools/equiv.py ADDR SRC` (omit `PES6_TARGET` for the resident executable).
